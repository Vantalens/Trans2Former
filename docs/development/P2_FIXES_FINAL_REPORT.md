### P2 #2: hashString 缓存优化

**影响**: 性能优化  
**提交**: `23b0a73`, `96da6eb`  
**文件**: `public/app.js:387-402` + 5 个失效点

**问题**: 每次调用都重新计算完整文档哈希，50KB+ 文档耗时 10-50ms

**解决方案**:
1. 实现 `updateCachedHistoryKey()` 函数
2. 使用 `cachedHistoryKey` 变量缓存结果
3. 在 5 个关键时机使缓存失效：
   - 文件名变化（handleInputText）
   - 输入内容变化（inputContent input 事件）
   - 输入格式变化（fromFormatSelect change）
   - 输出格式变化（toFormatSelect change）
   - Markdown 配置变化（markdownProfileSelect change）

**效果**:
- ✅ 减少重复哈希计算
- ✅ 提升大文档的 localStorage 读写性能
- ✅ 优化历史版本提交流程

### P2 #6: 文件队列增量渲染优化

**影响**: 用户体验  
**提交**: `c421474`  
**文件**: `public/core/file-queue-ui.js:16-93`

**问题**: 每次状态更新都重建整个队列 DOM，10+ 文件时卡顿明显

**解决方案**:
1. 使用 Map 索引现有 DOM 节点（O(1) 查找）
2. 复用现有节点，仅更新变化的属性：
   - active 状态（classList 操作）
   - status 文本和属性
   - 选中状态（check 文本）
3. 只创建新增的节点，移除不存在的节点
4. 使用 DocumentFragment 减少回流

**代码对比**:
```javascript
// 修复前：全量重建
listElement.replaceChildren(...fileQueue.map((item) => {
  const row = document.createElement("button");
  // ... 创建所有子元素
  return row;
}));

// 修复后：增量更新
const existingItems = new Map();
for (const child of listElement.children) {
  if (child.dataset?.queueId) {
    existingItems.set(child.dataset.queueId, child);
  }
}
// 复用现有节点，仅更新变化部分
```

**效果**:
- ✅ 10 个文件队列：10 次 DOM 操作 → 1-2 次
- ✅ 改善多文件批量处理的 UI 响应性
- ✅ 降低浏览器重排和重绘开销

1. **优先级选择**：
