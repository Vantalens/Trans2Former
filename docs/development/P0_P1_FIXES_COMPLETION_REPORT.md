## 经验教训

### 修复过程中的发现

1. **类型混淆是常见 bug 来源**
   - `getCapabilities()` 返回数组但被当作对象使用
   - 建议：TypeScript 或 JSDoc 类型注解

2. **历史兼容性需要显式处理**
   - Excel 1900 闰年 bug 需要代码级补偿
   - 建议：文档化所有兼容性决策

3. **输入验证必须全面**
   - Unicode 范围验证缺失导致崩溃
   - 建议：统一输入验证框架

4. **异步取消逻辑容易出错**
   - Promise 链中的错误处理需要特别小心
   - 建议：标准化取消模式

### 最佳实践

1. ✅ **每个修复独立提交** - 便于回滚和追踪
2. ✅ **修复前先写测试** - TDD 方法论
3. ✅ **完整测试套件验证** - 确保无回归
4. ✅ **清晰的提交信息** - 包含问题、修复、验证
